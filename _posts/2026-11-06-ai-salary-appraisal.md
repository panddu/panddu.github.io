회사에 흥미로운 스킬 하나가 돌았습니다. 이름하여 **'연봉감정사'**.

로컬의 Claude Code, Codex 세션 기록과 git 커밋 로그, 셸 히스토리를 샅샅이 뒤져서 점수를 매기고 가상의 오퍼레터(Offer Letter)를 발행해 주는 스킬이었습니다. 

호기심 반, 긴장 반으로 한번 돌려봤습니다.

---

### 1. 실측된 사용 패턴: "터미널을 열면 일단 에이전트부터 켠다"

스크립트가 로컬 데이터를 긁어모아 뽑아낸 제 사용 패턴은 꽤나 적나라했습니다.

* **세션 수**: Claude Code 319회 + Codex 39회 (총 358회)
* **몰입도**: 세션의 76%(244회)가 10월 한 달에 집중됨 (서서히 축적된 곡선이라기보단 특정 시점에 극단적으로 몰입한 형태)
* **명령 비율**: `Bash : Read = 8.1 : 1` (파일을 읽어달라고 얌전히 시키기보다 셸로 직접 까고 파고드는 타입)
* **커밋과 출하**: 180일간 25개 레포에서 **1,109건(하루 평균 6.2건)**
* **AI 공동 작성 비율**: **57.5%** (에이전트에게 코딩을 시키고 끝내는 게 아니라, 사람 손과 에이전트가 섞여서 출하 경로에 직접 올라간 상태)
* **코드 라인**: +807K / −373K (**삭제가 추가의 46%**)
* **하네스**: 직접 제작한 스킬 41개(팀 공용 29개, 개인용 12개), 훅 13종, MCP 8개
* **셸 히스토리 1위**: 터미널 1,046줄 중 `claude` 실행 150회

사실 10월 한 달 동안 세션이 이렇게 폭발했던 데는 명확한 이유가 있었습니다. 10월에 유독 실무 업무가 쏟아졌던 데다, 시스템 전반의 병목을 뚫어야 하는 **대규모 성능 개선 작업**들이 집중되어 있었기 때문입니다. 

로그를 찍고 프로파일링하며 병목 지점을 찾고, 비효율적인 쿼리와 로직을 뜯어고치는 과정에서 에이전트를 실전 무기로 완전히 쥐고 흔들었던 것이죠. `Bash : Read` 비율이 8:1로 치솟고, 삭제 라인 비율이 46%에 달했던 것도 결국 성능 개선과 레거시 정리를 위해 코드를 치열하게 쳐내며 튜닝했던 흔적이었던 셈입니다.

결과를 요약하면, **"터미널을 열면 일단 에이전트부터 띄워놓고, 혼자 쓰는 게 아니라 남들이 쓸 도구(스킬/하네스)를 만들며, 짠 코드를 끊임없이 지우고 고쳐가며 매일 코드를 내보내고 있는 사람"**으로 찍혔습니다.

### 2. 감정 결과: Senior AI DevEx Engineer

감정사가 매긴 총점은 **18점 만점에 12점 (Senior 밴드 상단)**이었습니다.

* **제안된 직무**: `Senior AI Developer-Experience Engineer (팀 에이전트 하네스 & 운영 자동화)`
* **가상 오퍼 (한국 테크 대기업 기준)**:
  * 기본급: 1.25억
  * 1년차 총보상(TC): 1.5억 ~ 1.6억
* **미국 베이에어리어(L5 기준)**: Base $235K / 총보상 $420K ~ $450K

단순히 코드를 짜는 1인 작업자가 아니라, **팀이 AI를 쓸 수 있도록 하네스와 스킬 레포를 깔아주고 운영하는 플랫폼 엔지니어** 성격이 강하다는 이유로 직무와 보상이 저렇게 책정되었습니다.

숫자만 보면 기분 좋을 법도 하지만, 리포트 뒷부분의 '숨겨진 구멍들'을 보면서 바로 현실로 돌아왔습니다.

### 3. 감정사가 보지 못한 것들: 1.8억 토큰과 '품질'의 부재

감정사 리포트 자체에도 뼈 때리는 면책 조항들이 달려 있었습니다.

#### ① 이 사람의 진짜 유지 비용은 얼마인가?
Claude Code 기록만 737MB, 텍스트로 치면 대략 **1.8억 토큰** 분량입니다. 게다가 호출의 97%가 가장 비싼 모델(Opus 계열)이었습니다. 
에이전트가 매 턴마다 수만 토큰의 컨텍스트를 다시 먹는 구조를 감안하면, 회사가 나를 고용해서 얻는 생산성 대비 **"이 사람이 쓰는 추론 비용(API 청구서)"**이 만만치 않다는 뜻입니다. 연봉 협상 테이블이라면 당연히 이 비용 청구서가 감점 요인으로 올라올 겁니다.

#### ② 사용 흔적은 '임팩트'를 증명하지 못한다
감정사가 본 것은 로컬의 **처리량, 도구 사용 취향, 출하 커밋 수**뿐입니다.
* 내가 만든 41개의 스킬을 팀원들이 실제로 매주 유용하게 쓰고 있는지?
* 에이전트와 함께 쏟아낸 1,100개의 커밋이 장애를 유발하진 않았는지?
* 그 코드가 비즈니스에 진짜 돈을 벌어다 줬는지?

이건 로컬 로그만으로는 절대 알 수 없는 영역입니다.

#### ③ '꾸준한 습관'인가, '실무 파도 대응'인가?
감정사는 10월 한 달에 세션이 집중된 것을 두고 "지속적인 습관인지 일시적 몰입인지 알 수 없다"며 지속성 점수를 깎았습니다. 겉으로 드러난 통계치만 보는 스크립트의 눈에는 그렇게 보이는 게 당연합니다.

하지만 현업 개발자의 시선에서는 조금 달랐습니다. 평온할 때의 루틴보다, **업무량이 폭증하고 성능 개선이라는 무거운 과제가 닥쳤을 때 에이전트를 실전 무기로 쥐어짜며 돌파구를 뚫어낸 기록**에 가까웠기 때문입니다. 기술이 진짜 쓸모를 증명하는 순간은 평화로운 날의 장난감이 아니라, 이런 파도가 칠 때라는 걸 체감한 한 달이기도 했습니다.

---

### 4. 도구를 만드는 게 진짜 생존 비법일까?

이 감정 결과를 보면서 가장 깊게 생각하게 된 질문은 이것이었습니다.

> **"도구를 만들 줄 아는 게 진짜 AI 시대의 생존 비법인가? 도메인 지식 없이 껍데기뿐인 스킬을 찍어내는 건 이제 누구나 에이전트에 시키면 10분 만에 하는 것 아닌가?"**

맞는 말입니다. 스킬 파일 몇 개 만들 줄 안다는 건 더 이상 기술적 해자가 아닙니다. "PR 요약해줘", "이 파일 읽고 포맷팅해줘" 같은 범용 래퍼 스킬은 누구나 만들 수 있고, 조만간 툴 자체의 기본 기능으로 흡수되어 사라집니다.

진짜 값이 붙는 건 **'스킬의 껍데기'가 아니라 '스킬 안에 무엇이 들어 있는가'**입니다.
* 특정 결제 수수료의 복잡한 예외 규칙
* 장애가 났을 때 실패 큐를 어떤 순서로 다시 인입해야 데이터 정합성이 깨지지 않는지
* 외부 연동 기관의 괴상한 에러 코드에 대응할 때 어느 매퍼를 참조해야 하는지

이런 건 에이전트가 인터넷을 아무리 뒤져도 절대 혼자 만들어낼 수 없습니다. 오직 그 조직에서 굴러보고 피 흘려본 사람의 머릿속에만 있는 **도메인 판단**이기 때문입니다.

결국 AI 시대의 경쟁력은 단순히 "스킬을 만들 줄 안다"가 아니라, **"내 머릿속에 갇혀 있던 도메인 지식과 업무 판단을, 에이전트가 실수 없이 실행할 수 있는 하네스(규칙·도구·맥락) 형태로 외재화할 수 있는가"**에 달려 있다는 생각이 들었습니다. 도구는 증폭기일 뿐이고, 핵심은 여전히 도메인 지식입니다.

### 마치며

감정 결과에 찍힌 1.5억이라는 숫자는 어디까지나 가상의 앵커일 뿐입니다. 10월의 폭발적인 몰입은 업무량과 대규모 성능 개선이라는 실무 파도가 맞물린 특수한 구간이었고, 이런 생산성과 도구 활용이 앞으로도 꾸준한 기본값으로 자리 잡을지는 계속 지켜봐야겠죠.

다만 한 가지 분명해진 건 있습니다.
코딩 에이전트가 쏟아져 나오는 시대에, "에이전트가 짜준 코드를 구경하는 관객"으로 남을 것인가, 아니면 "에이전트가 우리 도메인 위에서 제대로 춤출 수 있게 바닥을 깔아주는 사람"이 될 것인가.

적어도 지난 한 달간 제가 터미널과 씨름했던 358번의 세션은, 후자가 되기 위한 발버둥이었던 것 같습니다.
